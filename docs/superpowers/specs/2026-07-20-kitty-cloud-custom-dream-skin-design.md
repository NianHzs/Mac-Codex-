# 凯蒂猫云朵主题与自定义 Dream Skin 稳定链路设计

日期：2026-07-20
目标版本：1.3.43
适用平台：Windows

## 1. 目标

本次工作同时完成两项强相关改动：

1. 将用户提供的粉色云朵凯蒂猫图片加入“视觉个性化”，作为继“凯蒂猫限定主题 · 圣诞小屋”和“蜡笔小新限定主题 · 元气涂鸦”之后的第三款角色预设主题。
2. 修复自定义 Dream Skin 在界面显示“当前使用”但 Codex 实际没有换肤、应用失败时缺少明确反馈的问题。

不改变客户端蓝/粉皮肤切换，不影响账号、供应商、会话或其他已有设置。

## 2. 已确认现状与根因

用户提供的图片与当前自定义皮肤选择的图片内容一致：

- 原始尺寸：2848 × 1600
- 文件大小：2,933,895 字节
- SHA-256：`13bfa92e75c2150040f9e73f71bd14248e64cb63cfaadfc9d0b4139ce0f3306a`

当前自定义主题链路会在启动注入脚本生成阶段读取整张图片，并转换为约 4 MB 的 Base64 Data URI，再与完整主题运行时、CSS 和业务注入脚本一起通过 CDP 发送。该方案存在三个问题：

- 图片越大，注入消息越大，启动和重新注入更容易失败或超时。
- 自定义主题渲染失败时，前端 catch 分支直接恢复主题，没有把具体错误反馈给管理工具。
- 设置保存成功与页面主题渲染成功是两个不同状态，但现有按钮只依据设置判断“当前使用”，容易产生假成功。

项目已经提供本机图片地址 `/overlay/image`，但自定义 Dream Skin 分支仍优先依赖注入脚本中的 Base64 图片，没有使用这条更稳定的本机读取通道。

## 3. 方案选择

采用“服务器管理第三款主题 + 本机端点加载自定义图片”的组合方案。

不采用以下方案：

- 不把第三款图片永久打进安装包，否则以后替换图片必须重新发布客户端。
- 不继续扩大 Base64 注入脚本，否则只能缓解单张图片，无法解决用户继续选择大图时的稳定性问题。
- 不只增加第三张卡片而忽略自定义主题问题，避免再次出现界面可选但实际无效果。

## 4. 第三款预设主题

### 4.1 基本信息

- ID：`hello-kitty-cloud-dream`
- 名称：`凯蒂猫限定主题 · 云朵梦境`
- 描述：`粉色云朵首页、凯蒂猫梦境主视觉与柔粉功能卡`
- 类型：Dream Skin 浅色主题
- 权限：`restricted`
- 授权方式：沿用现有凯蒂猫与蜡笔小新主题的授权名单
- 主图：`kitty-cloud-dream.png`
- 缩略图：`kitty-cloud-dream-thumb.jpg`

### 4.2 视觉参数

- 背景：`#FFF7FA`
- 表面：`#FFFCFD`
- 强调色：`#D85B8C`
- 边框：`#F0D2DE`
- 正文：`#673B4A`
- 圆角：18 px
- 图片焦点：水平 50%，垂直 52%
- 安全文字区：左侧
- 工作区模式：ambient
- 布局：使用与现有两款限定主题相同的卡片式 Dream Skin 渲染

主图保持原始宽高比，不裁切源文件。缩略图只用于管理工具卡片预览，允许等比例缩放和居中裁切以减少网络加载体积。

### 4.3 服务端数据

主题服务的 manifest 增加第三项，并在授权列表中增加 `hello-kitty-cloud-dream`。客户端不硬编码授权结果，继续以服务端返回的 `allowedThemeIds` 为准。

## 5. 自定义 Dream Skin 新链路

### 5.1 保存阶段

选择图片后仍只更新表单状态；点击“应用自定义皮肤”时必须一次性保存：

- `codexAppImageOverlayEnabled = true`
- `codexAppImageOverlayPath`
- `codexAppVisualThemeEnabled = true`
- `codexAppVisualThemeId = custom-dream-skin`

保存返回失败时停止重启，并显示“主题设置保存失败”。

### 5.2 图片加载阶段

启动注入脚本不再嵌入完整自定义图片 Base64。注入配置只提供：

- 是否启用
- 透明度与适配模式
- 本机图片 URL
- 图片格式信息

自定义 Dream Skin 激活时，通过 `http://127.0.0.1:<helper-port>/overlay/image` 获取图片。获取成功后创建 Blob Object URL，再交给 Fei-Away Dream Skin 渲染器；切换主题或恢复默认时撤销旧 Object URL，避免长期占用内存。

只有服务器管理的预设主题继续通过 `/theme/assets` 加载，二者互不混用。

### 5.3 状态与错误反馈

主题应用状态区至少区分：

1. 正在保存设置
2. 正在关闭旧主题
3. 正在重启 Codex
4. 正在加载本地壁纸
5. 已应用
6. 应用失败及具体原因

管理工具中的“当前使用”仍表示选中的配置。渲染器通过现有 `/diagnostics/log` 通道记录 `dream_skin_applied` 或 `dream_skin_apply_failed`；管理工具在重启后的状态刷新中读取最新主题结果。当运行时报告图片读取或渲染失败时，同时显示醒目的失败状态，不再静默恢复。

## 6. 安全与限制

- 仅允许 PNG、JPEG 和 WebP 用作 Dream Skin 图片；文件选择器与后端验证保持一致，不再展示实际不能应用的 GIF/BMP。
- 图片必须是普通文件，路径必须存在且可读。
- 本机图片接口只监听回环地址，不向外部网络暴露用户图片。
- 不把本机文件路径或图片内容上传到主题服务器。
- 服务端预设图片仍执行类型、大小、文件名和授权检查。

## 7. 测试设计

### 7.1 前端测试

- 第三款主题在授权后可见，未授权时按钮禁用。
- 第三款主题具有正确名称、ID、主图和缩略图。
- 自定义主题应用时完整保存图片路径与主题 ID。
- 自定义主题失败时显示错误，不把失败状态标记为已应用。
- 文件选择器只允许 PNG/JPEG/WebP。

### 7.2 Rust 测试

- 注入脚本配置不再包含自定义图片的大型 Base64 内容。
- `/overlay/image` 对有效 PNG/JPEG/WebP 返回正确 Content-Type。
- 文件缺失、不支持格式或不可读时返回明确失败。
- 第三款主题 manifest、资源哈希与资源大小一致。

### 7.3 页面回归测试

- 三款角色主题的标题栏按钮位置和点击层保持正常。
- 第三款主题在首页、任务页和右侧面板中不覆盖文字。
- 自定义图片应用后，重启 Codex 仍保持该主题。
- 恢复官方默认后移除 Dream Skin 样式与本地图片。

## 8. 发布与回滚

- 客户端版本升级到 1.3.43。
- 先部署主题服务资源与 manifest，再发布客户端安装包和自动更新清单。
- 发布后从公网下载安装包并校验 SHA-256。
- 若第三款资源异常，可从服务端 manifest 暂时移除该主题，不要求用户重新安装客户端。
- 若自定义主题运行时异常，用户可点击“恢复官方默认”，原账号与其他设置保持不变。

## 9. 完成标准

- 视觉个性化页面显示三张角色主题卡片。
- 有权限用户可应用“凯蒂猫限定主题 · 云朵梦境”。
- 当前 2.93 MB 用户图片可以作为自定义 Dream Skin 成功应用并在重启后保持。
- 应用失败时用户能看到可理解的错误原因。
- 标题栏按钮、侧边按钮和对话文字无位移、遮挡或无法点击问题。
- 1.3.43 安装包、本地安装版本和服务器更新清单保持一致。

# ♛Codework AI 客户端 Windows Dream Skin 整合设计

## 目标

将 `C:\Users\19128\Desktop\codexSkin\windows` 的成熟 Codex Dream Skin 技术整合进 ♛Codework AI客户端的“个性化”页面，仅支持 Windows。

用户不需要安装、运行或理解独立的 Dream Skin 脚本、托盘和快捷方式。用户在客户端选择主题并点击“应用”后，官方 Microsoft Store Codex/ChatGPT 的页面才启用皮肤。

## 已确认的产品决策

- 入口只在客户端“个性化”页面；不创建独立 Dream Skin 托盘、桌面快捷方式或开始菜单项。
- 主题仅在用户点击应用后生效。
- 已由客户端带调试接口启动的 Codex 支持热切换；普通方式启动的 Codex 需要经用户确认重启一次后应用。
- 仅支持 Windows 上已注册的官方 Microsoft Store `OpenAI.Codex` 客户端。
- 会员、指定用户 ID、管理员和创始人主题权限必须由服务器核验，不能只在前端隐藏按钮。
- 主题内容、预览图和权限可从服务器实时更新；换肤引擎本身随客户端版本更新。

## 采用方案

采用“原版渲染层 + Codework 原生控制层”。

`codexSkin` 中已验证的 Dream Skin CSS、渲染器、主题 JSON 协议、CDP 安全校验原则和验收用例作为上游基线。Codework 不运行独立 PowerShell/Node 托盘引擎，而是在现有 Rust/Tauri 启动器中实现对应的 Windows 生命周期控制。

这样可以保留成熟视觉效果和交互保护，同时避免用户看到脚本窗口、依赖 Node.js、出现两套状态文件或多个换肤后台进程。

## 架构

```text
个性化页面
  ├─ 主题库 / 预览 / 应用 / 暂停 / 恢复
  └─ 显示真实状态与进度
             │
             ▼
Tauri 命令层
  ├─ 授权与主题同步
  ├─ 本地主题仓库
  ├─ Dream Skin 生命周期控制
  └─ 注入结果验证
             │
             ▼
Windows CDP 运行层
  ├─ 官方 Store 包身份校验
  ├─ 仅回环调试端口与 Browser ID 锚定
  ├─ 首屏提前注入与刷新恢复
  ├─ 主题热切换
  └─ 安全清除与失败回滚
             │
             ▼
官方 Codex / ChatGPT 主窗口
  └─ 原生侧栏、项目选择、输入框和任务内容 + Dream Skin 外观
```

## 模块边界

### 1. `dream_skin_runtime`

Windows 专用运行模块，负责：

- 动态发现并校验当前已注册的 `OpenAI.Codex` Store 包。
- 使用 `--remote-debugging-address=127.0.0.1` 和随机可用端口启动官方客户端。
- 校验 CDP HTTP 与 WebSocket 均为相同端口的回环地址。
- 固定启动时的 Browser ID；端口被其他进程复用或 Browser ID 变化时立即停止，不连接未知页面。
- 只在确认具有 Codex 主界面标记的 renderer 注入。
- 使用早期注入保证刷新和路由切换后的首屏稳定，再以加载事件作为兼容兜底。
- 支持 `apply`、`pause`、`resume`、`restore`、`verify` 五种操作。

### 2. `dream_skin_store`

本地主题仓库位于：

```text
%LOCALAPPDATA%\CodeworkAIClient\DreamSkin\
  active-theme.json
  themes\<theme-id>\theme.json
  themes\<theme-id>\background.*
  cache\
  state.json
  logs\
```

仓库必须拒绝路径逃逸、junction、符号链接和异常大图片。图片最大 16 MB，任一边最大 16384 像素，总像素不超过 50 MP。写入使用同目录临时文件和原子替换。

### 3. `dream_skin_assets`

上游 Dream Skin 渲染器和 CSS 作为带版本、哈希和第三方声明的 vendored assets 管理。

Codework 专属能力通过薄适配层提供主题数据，不在上游原文件中混入会员、广告、聊天、皇冠或服务端逻辑。这样后续升级上游版本时可以进行可审计的文件差异对比。

### 4. `dream_skin_entitlement`

现有客户端会员令牌向服务端请求主题清单。服务端返回：

- 可用主题 ID 列表。
- 每个主题的展示信息、图片地址、SHA-256、revision 和到期时间。
- 当前用户的身份等级及专属主题许可。

客户端不信任本地用户 ID 白名单。没有权限的主题不下载、不返回真实资源地址，也不能通过改前端状态绕过。

## 用户流程

### 应用主题

1. 用户在个性化页面选择主题，点击“立即应用”。
2. 客户端先核验会员会话和主题授权，下载并校验主题资源。
3. Codex 未运行：客户端以安全回环调试参数启动官方 Codex 并应用主题。
4. Codex 已由 Codework 启动：热切换主题，不重启。
5. Codex 普通启动：显示一次明确确认，用户同意后关闭并以安全参数重启。
6. 注入完成后检查主题标记、原生侧栏、项目选择和输入框；全部通过才显示“已生效”。

### 暂停、恢复与失败

- 暂停：保留当前选择，只移除当前页面的主题样式与装饰。
- 继续：以已校验缓存重新应用。
- 恢复默认：移除提前注入脚本、CSS、装饰 DOM 与运行态记录；官方界面恢复正常。
- 应用失败：自动清理本次残留，再显示可理解的原因和“重新检测”按钮。

## 视觉隔离规则

客户端自身蓝/粉外观与官方 Codex 页面主题必须彻底隔离：

| 层级 | 负责对象 | 不能影响 |
|---|---|---|
| Codework Client Skin | ♛Codework AI客户端的窗口、导航、聊天、身份 UI | 官方 Codex 页面 |
| Dream Skin | 官方 Codex/ChatGPT 主窗口的背景、阅读层、首页与任务页 | 客户端皇冠、聊天浮层、管理员身份 |
| Identity UI | 客户端的皇冠、头像、VIP 标签、管理员控制 | Dream Skin 色板 |

Codex 页面只允许一个 Dream Skin 渲染器拥有主题 class、style 元素和装饰 DOM。现有旧 Codework Codex 换肤逻辑需要在迁移完成后停用，不能与上游 Dream Skin 同时注入。

渲染规则：

- 背景和装饰元素必须 `pointer-events: none`。
- 原生控件保持在上层并可点击。
- 首页使用完整视觉；对话、代码和任务页使用更强的阅读遮罩。
- 主题切换先清理旧 revision，再注入新 revision。
- 辅助窗口、宠物窗口、登录窗口和非主窗口强制清除主题残留。

## 主题类型

- 基础主题：所有人可用的 Codework 品牌主题。
- 会员主题：按 VIP/至尊 VIP 授权。
- 专属主题：按用户 ID、创始人、管理员、活动奖励授权。
- 自定义主题：用户导入背景，客户端根据亮度、焦点、安全留白、任务页模式生成本地主题数据。

凯蒂猫、蜡笔小新等第三方角色素材可以作为技术能力支持的主题类型，但不能默认内置到公开或收费分发包，除非具备授权。对外默认主题使用原创或已授权素材；用户私有导入的图片不上传服务器。

## 主题实时更新

客户端打开个性化页、启动 Codex 前和定时刷新时拉取主题清单。

- 相同主题仅在 `revision` 或 SHA-256 变化时下载。
- 新主题资源下载到临时目录，完整校验后再原子替换缓存。
- 下载或校验失败继续使用上一个完整版本。
- 服务器修改主题文案、预览、图片或权限时，不需要重新发客户端安装包。
- 授权采用短期签名缓存；短时断网允许继续使用已验证缓存，超过有效期后下一次应用或启动需要重新核验。

## 迁移策略

1. 保留现有“个性化”页面和服务端主题接口。
2. 引入新的 Dream Skin 状态机和原版渲染资产。
3. 将现有主题映射为新主题清单格式。
4. 只在新引擎验证通过后关闭旧 Codex 换肤注入路径。
5. 保留“恢复官方界面”作为永久兜底入口。
6. 不影响客户端自身蓝粉主题、会员身份、聊天、公告、Skill 市场和中转设置。

## 验收与测试

自动测试覆盖：

- 主题 JSON、权限、哈希、缓存和资源大小校验。
- Store 包身份、回环 URL、Browser ID、目标窗口筛选和端口复用拒绝。
- 首屏注入、页面刷新、路由切换、热切换、暂停和恢复。
- 主题不会覆盖文本或拦截点击。
- 主窗口可注入，辅助窗口必定清理。
- 主题资源下载失败和注入失败的回滚。

人工验收覆盖：

- 首页、普通对话、长代码会话、设置页。
- 侧栏、项目选择、输入框、发送、菜单、弹窗。
- 窗口缩放、刷新、切换会话、切换项目、客户端更新后的重新适配。

## 不在本次范围内

- macOS Dream Skin。
- 在 WindowsApps 或 `app.asar` 内直接修改官方程序。
- 独立 Dream Skin 托盘、快捷方式、PowerShell 安装器。
- 未获授权的第三方角色或真人素材随公开安装包分发。

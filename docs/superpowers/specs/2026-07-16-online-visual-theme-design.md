# 在线视觉个性化主题设计

## 目标

让 Codework Codex++ 的「视觉个性化 Pro」从用户的 1Panel 主题服务读取可更新的主题清单。用户在管理器输入 `http://服务器公网 IP:28080` 并刷新后可看到服务器版本和主题；选中主题并重启 Codex++ 后生效。服务器后续修改同一主题的外观参数，运行中的 Codex 会定时拉取并刷新。

## 范围与安全边界

- 服务只发布 JSON 清单；客户端只接受主题 ID、名称、说明和受限视觉参数（颜色、圆角、字号）。不下载、不保存、不执行远程 CSS 或 JavaScript。
- 现有四个内置主题仍可离线使用。网络失败时管理器显示上次缓存或内置主题，并且不影响当前已应用主题。
- 主题服务地址是公开地址，不含令牌。暂不实现激活码、设备标识、支付回调等敏感信息的 HTTP 传输；这些功能等 HTTPS 可用后单独接入。

## 数据与流程

清单格式包含 `version`、`updatedAt` 和 `themes`。每个主题包含稳定的短 ID、可显示文本、`tier: "pro"`、版本与 `tokens`。tokens 仅允许 `background`、`surface`、`accent`、`border`、`text`、`radius` 与 `fontScale`；管理器和注入器各自校验，避免服务端数据被篡改时突破边界。

管理器把服务地址保存到现有 `BackendSettings`，把最近一次有效清单缓存到 localStorage。页面首次进入和点击刷新均请求 `/v1/themes/manifest`；成功后以在线主题覆盖同 ID 的内置主题并显示服务版本。主题选择保存主题 ID 与服务地址，再重启 Codex++。

注入器先用内置 token 立即渲染，随后从已保存服务地址请求清单。如当前主题在合法在线清单中，使用其 token 更新 style 标签；每五分钟刷新一次。恢复官方默认会删除该 style 标签并停止产生可见主题效果。

## 验证

源码回归测试检查：设置字段贯通 Rust 与 React；清单包含 token 合约；注入器含安全 token 校验、受限 CSS 生成和在线清单端点。TypeScript 检查与主题服务语法检查必须通过。

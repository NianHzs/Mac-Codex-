# ♛Codework AI客户端 1.3.37—1.4.0 产品完善设计

日期：2026-07-19

状态：已完成对话设计确认，待用户审阅文档

当前稳定基线：1.3.36

## 1. 背景

♛Codework AI客户端已经具备模型配置、会员登录、身份展示、Codex/ChatGPT 个性化、Skill 市场、活动中心、公告、超话、好友私聊和客户端更新等能力。当前主要问题不是缺少功能，而是功能增长速度已经超过底层稳定性、统一视觉和维护结构的承载能力。

现有代码中，前端主入口 `App.tsx` 约 8099 行，Tauri 后端命令文件约 5323 行，Codex 注入脚本约 9261 行。更新清单目前只包含版本、下载地址和更新说明；API Key 与会员令牌仍跟随设置文件持久化；聊天主要依靠定时轮询。这些现状会提高回归故障、敏感信息泄露、更新失败和 UI 不一致的概率。

本设计采用分版本基础优先路线，不进行一次性重写。每个版本必须能够单独测试、覆盖安装、发布和回滚。

## 2. 总体目标

1. 将更新流程升级为可校验、可确认、可回滚的可靠更新链路。
2. 保护 API Key、登录令牌和主题会员令牌，自动迁移现有用户配置。
3. 建立统一、专业且可长期扩展的曜石视觉设计系统。
4. 拆分超大文件和耦合模块，降低修改单个功能造成连锁回归的风险。
5. 将聊天升级为可靠的实时好友与消息系统。
6. 建立服务端驱动的公告、活动、Skill、主题、权益和版本发布体系。
7. 保持账号、模型配置、主题选择、聊天关系和其他既有用户数据不丢失。

## 3. 非目标

- 不在一个版本内同时重写全部客户端与服务器。
- 不改变现有官方账号体系的用户标识。
- 不把视觉身份切换当作真实权限切换。
- 不允许客户端本地配置直接授予付费权益或管理员权限。
- 不采集聊天正文、API Key、密码或永久登录令牌作为运营数据。
- 不要求每次公告、活动、主题或 Skill 内容更新都重新发布客户端。

## 5. 曜石身份视觉系统

### 5.1 视觉原则

整体采用已确认的 C 方案“曜石高级感”。界面基础色使用曜石黑、深灰和低饱和中性色，身份颜色只用于皇冠、头像边框、身份卡、状态高光和少量氛围光，避免所有用户看到满屏暗红。

### 5.2 身份颜色

| 身份 | 颜色与表现 |
| --- | --- |
| 创始人 / 平台执掌者 | 暗红皇冠、暗红身份卡与克制的氛围光 |
| 总监 | 银蓝色皇冠和边框 |
| 管理员 | 皇家蓝皇冠和边框 |
| 至尊 VIP | 金色皇冠和权益高光 |
| 普通 VIP | 低饱和浅蓝，明显弱于管理员与总监 |
| 普通用户 | 中性银灰 |

真实管理权限只能来源于服务器返回的实际管理员字段。管理员切换体验身份只改变体验范围内的身份展示，不改变真实授权。

### 5.3 三层主题优先级

1. **基础视觉层**：曜石布局、组件、间距、字体、圆角和阴影。
2. **客户端皮肤层**：保留蓝色、粉色等可选皮肤，改变普通按钮、卡片和装饰高光。
3. **身份层**：皇冠、头像边框、身份名称和身份卡始终由真实或经过授权的体验身份决定，优先级最高。

Codex/ChatGPT 的凯蒂猫、蜡笔小新和自定义皮肤属于独立系统，不得覆盖客户端主题，也不得被客户端蓝粉皮肤覆盖。

## 6. 1.3.37：稳定安全基础版

### 6.1 可信更新清单

更新清单扩展为以下核心字段：

```json
{
  "version": "1.3.37",
  "downloadUrl": "http://example/downloads/client-1.3.37.exe",
  "size": 15332386,
  "sha256": "HEX_SHA256",
  "signature": "BASE64_ED25519_SIGNATURE",
  "publishedAt": "2026-07-19T12:00:00Z",
  "minimumSupportedVersion": "1.3.36",
  "mandatory": false,
  "notes": []
}
```

客户端内置发布公钥。下载完成后依次校验文件大小、SHA-256 和 Ed25519 数字签名，任一校验失败均停止安装并保留当前版本。

### 6.2 更新数据流

1. 客户端读取服务器最新版清单。
2. 比较规范化版本号。
3. 下载到独立临时目录，不覆盖安装目录。
4. 校验大小、哈希和签名。
5. 检查磁盘空间、安装目录写入权限和旧进程状态。
6. 记录目标版本与当前版本，启动静默安装器。
7. 安装器关闭旧进程，备份现有两个 EXE，原子替换程序文件。
8. 启动新版管理端。
9. 新版确认自身版本与目标版本一致并写入成功状态。
10. 若启动失败、版本不符或超时未确认，则恢复上一版并记录回滚原因。

清单切换和安装包发布必须保持顺序：先上传版本化安装包，完成公网校验，再原子切换最新版清单。

### 6.3 敏感信息存储

以下内容从普通设置 JSON 中迁移到 Windows DPAPI 保护的本地凭据存储：

- 中转站 API Key。
- 官方账号登录令牌与刷新令牌。
- Codex 主题会员令牌。
- 其他供应商的敏感认证字段。

首次启动时执行一次性迁移：读取旧明文值、写入加密存储、验证可解密、再清除设置文件中的明文。迁移失败时不删除原值，并向用户显示可理解的修复提示。

### 6.4 配置备份与恢复

- 自动备份模型配置、主题选择、供应商分组和非敏感偏好。
- 默认导出不包含明文密钥。
- 支持升级前自动备份、手动备份、预览恢复内容和恢复前二次确认。
- 每个备份包含配置架构版本，用于后续迁移。

### 6.5 一键体检与修复

体检范围包括：

- 两个客户端 EXE 版本是否一致。
- 本机版本与服务器清单是否同步。
- 更新包下载、签名、权限和磁盘空间。
- ChatGPT、账号服务、中转服务、主题服务和活动服务连接。
- 配置文件格式、重复配置和已知冲突。
- 最近一次更新阶段、失败原因和回滚结果。

普通用户看到结果、原因和建议操作。管理员可导出脱敏支持包。支持包不得包含 API Key、密码、永久令牌和聊天正文。

### 6.6 1.3.37 UI 范围

建立曜石设计变量和基础组件，首批迁移登录页、首页、账户中心、版本更新与体检页。其他页面保持功能稳定，在 1.3.38 迁移。

## 7. 1.3.38：完整 UI 与代码模块化

### 7.1 前端边界

前端拆分为以下功能域：

- 应用外壳与导航。
- 登录与账号。
- 首页、公告和服务状态。
- 模型供应商与令牌分组。
- 客户端皮肤与 Codex 个性化。
- Skill 市场。
- 活动、超话与公告管理。
- 好友与私聊。
- 版本更新、诊断与配置备份。
- 管理员控制中心。

页面不直接拼装大量 Tauri 命令调用。每个功能域通过自己的服务层和类型化接口访问后端，统一处理加载、成功、空状态和错误。

### 7.2 后端边界

将超大命令文件拆分为账号、发布更新、供应商、主题、社区聊天、Skill、诊断、配置迁移和管理员功能模块。公共网络客户端、错误类型、脱敏日志和响应结构放入共享基础层。

### 7.3 Codex 注入边界

注入逻辑拆分为：

- 启动与兼容性检测。
- 主题运行时。
- 凯蒂猫主题适配器。
- 蜡笔小新主题适配器。
- 自定义主题适配器。
- 身份皇冠与状态展示。
- 图片叠加与浮层。
- ChatGPT/Codex 版本兼容规则。

每个适配器必须在目标节点不存在时安全退出，不能因为页面结构变化遮挡侧栏文字或破坏对话交互。

### 7.4 页面体验

完整迁移登录、首页、账户、模型配置、个性化、Skill 市场、活动、超话、聊天、更新和管理员页面。统一使用专业图标、间距、组件状态、悬停说明、二次确认和响应式布局。

蓝色与粉色皮肤继续保留为客户端可选皮肤。身份色与 Codex 个性化主题按照第 5.3 节的优先级隔离。

### 7.5 性能

- 页面和重型模块按需加载。
- 合并重复状态请求，避免多个计时器重复刷新同一数据。
- 降低首页和聊天浮层的无效重渲染。
- 对慢接口显示局部加载，不阻塞整个客户端。

## 8. 1.3.39：实时聊天与好友系统

### 8.1 连接与认证

客户端登录后向账号服务申请短期聊天票据，再建立 WebSocket 连接。永久令牌不得放入 WebSocket URL 或服务器访问日志。当前未部署 HTTPS 的环境使用短期票据降低暴露范围；域名与证书就绪后切换到 WSS，不改变客户端消息协议。

### 8.2 好友搜索规则

- 仅能搜索官网已注册用户。
- 使用 ID 搜索时，结果不显示用户名。
- 使用用户名搜索时，结果不显示用户 ID。
- 支持发送、取消、同意、拒绝、删除、拉黑、解除拉黑和举报。
- 平台执掌者作为默认联系入口，但管理员好友列表不会自动包含全部用户。
- 只有用户主动向管理员发送消息后，管理员端才建立对应会话。

### 8.3 消息状态

每条消息拥有客户端消息 ID 和服务器消息 ID，状态依次为发送中、已发送、已送达、已读或失败。重连重发使用客户端消息 ID 保证幂等，防止重复消息。

离线消息通过服务器游标补发。客户端重连时携带最后确认游标，服务器返回缺失消息和最新未读计数。

### 8.4 消息能力

- 文字、Emoji、收藏表情。
- 图片、视频和文件。
- 粘贴、拖拽、选择文件和上传进度。
- 回复、引用、复制、撤回自己的消息。
- 自定义头像、默认头像库、裁剪和预览。
- 双击好友打开独立聊天框，右侧好友浮层可关闭和恢复。
- 当前打开的会话保持稳定，不因新消息强制跳到列表顶部。

附件上传使用独立对象存储或受控下载目录，限制文件类型、大小和上传频率。聊天记录只保存附件元数据和授权地址。

### 8.5 在线状态与提醒

- 在线：声音、任务栏提醒和轻微抖动。
- 请勿打扰：接收消息但不播放声音、不抖动。
- 隐身：对外显示离线，自己仍可正常收发消息。
- 离线：显示最后在线时间。

抖动和声音具有频率限制与单独开关。身份皇冠、头像边框和身份名称跟随真实或获准体验身份更新。

### 8.6 隐私

超话继续使用姓名脱敏。私聊内容不进入普通诊断日志。管理员具有平台治理能力，但默认不存在浏览全部用户私聊内容的客户端入口。

## 9. 1.4.0：运营、权益与发布后台

### 9.1 管理员控制中心

只有服务器确认的真实管理员可进入。管理范围包括公告、活动、用户身份、付费权益、Skill、主题、版本发布、回滚和用户主动提交的脱敏诊断。

视觉身份切换不得改变该入口的可见性或权限。

### 9.2 发布后台

发布流程为：

1. 选择安装包。
2. 自动读取 EXE 版本和大小。
3. 计算 SHA-256 并生成数字签名。
4. 填写公开更新说明和内部技术说明。
5. 上传版本化安装包与版本化清单。
6. 从公网地址重新下载并校验哈希。
7. 检查安装包版本、右上角版本、清单版本和下载地址一致。
8. 校验通过后原子切换最新版清单。
9. 支持暂停、灰度、恢复和一键回滚上一版。

历史安装包和历史清单保留，发布后台记录操作者、时间、版本、哈希、发布结果和回滚原因。

### 9.3 服务端内容

公告、活动、Skill 和主题均由服务器实时控制，不要求重新发布客户端。

公告支持投放范围、重要程度、置顶、开始时间、结束时间和最低客户端版本。活动中心展示已有活动，并通过短期单点登录票据在浏览器打开，避免用户重复登录。抽奖网站本身的功能升级不要求用户重新安装客户端。

### 9.4 身份与付费权益分离

- 创始人、总监、管理员属于身份与管理体系。
- 至尊 VIP、普通 VIP 属于会员身份。
- 个性化 Pro 是独立付费权益，价格保持 99 元。
- 支持永久、限时、赠送、指定用户 ID 授权和撤销。
- 客户端只展示服务器返回的权益，不信任本地篡改结果。

账户中心分别显示真实身份、体验身份、会员等级、Pro 权益和到期时间，避免把 Pro 与至尊 VIP 混为一类。

### 9.5 首次使用向导

首次启动依次完成：官方账号登录、官方 ChatGPT 检测与微软商店安装入口、供应商与令牌配置、接口测试、客户端皮肤选择、Codex 个性化选择、首次配置备份和进入工作台。

向导允许跳过非关键步骤，并可从体检中心重新运行。官方 ChatGPT 安装过程展示明确进度和结果，失败时提供可理解的替代操作。

### 9.6 Skill 市场

- 使用中文名称、功能说明、使用场景、版本和作者信息。
- 安装前显示来源、权限和文件清单。
- 只自动安装经过签名的官方或已审核 Skill。
- GitHub 可以作为来源，但包必须经过服务器审核与签名。
- 支持安装、更新、卸载、失败恢复和版本回退。
- 在指定说明区域展示安装方式、使用提示和适用范围。

### 9.7 运营与反馈

用户主动同意后才能上传脱敏诊断包。可统计版本分布、更新成功率、接口健康度和功能使用趋势，但不得采集聊天正文、API Key、密码和永久令牌。

旧版保留基础功能。只有严重安全问题可以标记强制升级。服务器 API 使用版本化路由或兼容字段，避免服务器升级导致旧客户端同时不可用。

## 10. 错误处理原则

1. 更新校验、备份或安装失败时优先保证旧版仍可启动。
2. 网络错误不得清空本地登录状态、模型配置或主题选择。
3. 服务端内容加载失败时显示上次成功缓存，并标明缓存时间。
4. 聊天发送失败必须保留草稿和重试入口。
5. 配置迁移只有在新存储验证成功后才能删除旧数据。
6. 管理员操作必须进行服务器权限校验，客户端隐藏按钮不能代替权限控制。
7. 用户可见错误使用中文说明“发生了什么、是否影响使用、下一步怎么做”；技术错误进入脱敏日志。

## 12. 成功标准

- 更新安装成功率可统计且稳定，任何失败均不会伪装成成功。
- 更新包被篡改时客户端拒绝安装。
- 设置文件中不再出现明文 API Key 和永久令牌。
- 全部页面遵守同一曜石设计系统和身份色规则。

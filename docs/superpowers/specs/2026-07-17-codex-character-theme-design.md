# Codex 角色限定主题设计

## 目标

为 `♛Codework AI客户端` 中启动的 Codex 对话界面提供两套仅限指定用户使用的完整视觉主题：

- 凯蒂猫主题：粉白、圣诞小屋主视觉、柔和粉色功能卡与输入区。
- 蜡笔小新主题：奶油黄、角色拼贴主视觉、暖橙功能卡与输入区。

主题作用于 Codex 的对话页面，不改变 Codework 管理客户端自身的默认管理界面。视觉效果以用户确认的「角色主视觉版」预览为基准：侧栏、首页 Hero、功能卡、输入框和按钮为同一视觉系统，角色图片在主视觉中保持清晰可见。

## 实现方式

沿用当前 Codework 的 renderer 注入架构，不修改 Codex 的安装包或 `app.asar`：

1. Codework 启动 Codex 后注入主题运行时。
2. 注入层读取本机主题选择与授权缓存，按稳定 DOM 锚点应用 CSS 变量、布局样式和背景图。
3. 页面导航、渲染重载和重新启动后，注入层检测主题标记是否存在；缺失时再次应用。
4. 不能匹配当前 Codex 页面结构时不强制覆盖，移除主题样式并保留官方界面。

该方式与 GitHub 的 CodeDrobe / Skin Studio 类方案一致：主题是可恢复的渲染层，而非篡改官方应用文件。

## 主题包

每个主题包包含：

- `id`、名称、版本与最小客户端版本；
- 背景图片和缩略图；
- 配色令牌：页面底色、侧栏、功能卡、输入框、按钮、文本与边框；
- 完整布局样式：Hero、卡片、侧栏导航、输入框、滚动条和悬浮按钮；
- 可读性规则：Hero 图片使用浅色渐变遮罩，正文与输入区域保持不透明或高透明度浅色卡；
- 完整性校验值，下载后校验再启用。

主题素材由主题服务提供，客户端保存已验证缓存。已有缓存时可离线继续使用；刷新失败不清除正在使用的主题。

## 授权与实时更新

用户登录 Codework 官方账号后，客户端使用现有身份 token 请求主题清单。服务端依据账号的用户 ID 返回：

- 可浏览的主题预览；
- 当前账号允许启用的 `themeIds`；
- 已授权主题的资源地址与版本。

未授权用户只能看预览和「限定主题」说明，不取得完整主题资源，也不能点击应用。管理员在现有服务器后台为用户 ID 添加或删除主题权限；客户端重新打开个性化页、手动刷新或下次启动时读取最新授权，无需重新安装客户端。

## 用户界面

视觉个性化 Pro 页面新增两张限定主题卡：

- 凯蒂猫限定主题 · 圣诞小屋；
- 蜡笔小新限定主题 · 元气涂鸦。

获授权用户显示「立即应用」；未授权用户显示「限定主题 · 请联系管理员开通」。应用前显示缩略预览，应用成功后显示当前主题与「恢复官方默认」操作。恢复默认只撤销主题样式与本地选择，不删除账号、会话、供应商配置或其它客户端设置。

## 稳定性与回退

- 注入样式以独立主题根标记限定，绝不使用全局粗暴覆盖。
- 每次应用保存上一个可用主题；新主题资源或 DOM 校验失败时自动回退。
- Codex 页面变更后无法找到约定锚点时静默放弃视觉覆盖，并提供「恢复默认」入口。
- 主题下载失败、权限过期、图片加载失败都保留原界面可用性，不阻断聊天、登录、模型选择或更新。
- 测试覆盖授权状态、资源校验、缓存、切换、重启重注入、手动恢复和 DOM 不兼容回退。

## 验收标准

1. 两张主题在 Codex 首页的结构与已确认预览一致：角色图显眼、浅色内容卡、文字不被背景遮挡。
2. 指定用户 ID 可启用，未授权用户不可启用。
3. 管理员调整授权后，用户不需重新安装客户端即可刷新生效。
4. 主题切换、页面刷新、Codex 重启后保持生效。
5. 恢复默认后完全回到官方 Codex 外观，账号和现有配置不变。
6. 资源、授权或 DOM 兼容性异常时不影响 Codex 正常使用，并自动安全回退。
